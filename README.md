# 10th-web-study

## 🌲 브랜치 규칙
- **브랜치 명** : `week00_닉네임_missionN`
- **생성 방식**: 이전 미션 브랜치에서 파생하여 작업 내역을 누적합니다.
  - (ex: `week01_Elric_mission1` → `week01_Elric_mission2` → `week01_Elric_mission3`)

---

## 📂폴더 구조
- 현재 진행하는 주차에 자기 닉네임으로 프로젝트를 생성합니다.
- 해당 프로젝트에서 실습을 진행해주시면 됩니다.
```
├── Main Page
│    └── Elric
│    └── README.md
└── README.md
```

## ✅ Pull Request 규칙
- PR 제목: [ 누가 올렸는지 ex) 찬서 ] 어떤 부분을 수정했는지 대략적인 제목 ex) 로그인 기능
- 내용 : 세부내용 및 어느 부분에 문제가 있는지

PR 작성 이후에 우측부분에서 Reviewer 및 Assignee 지정해주세요!

### Reviewer & Assignee
- Reviewer : 최상위 권한 있는사람 지정 (확인하는 사람)
- Assignee : 본인(작성자) 지정

📍 **Merge 규칙 :
PR 병합은 해당 레파지토리 주인이 최종 Merge (그 외 인원은 Merge 하지 않음)**
  
---

## ✅ 커밋 메시지 규칙
| 타입      | 설명 |
|-----------|------|
| feat      | 새로운 기능 추가 |
| fix       | 버그 수정 |
| docs      | 문서 수정 (README, 주석 등) |
| style     | 코드 스타일 변경 (포맷, 세미콜론 등) |
| refactor  | 리팩토링 (기능 변화 없음) |
| test      | 테스트 코드 추가 / 수정 |
| chore     | 빌드 설정, 패키지 관리 등 기타 작업 |
| build     | 빌드 관련 파일 수정 |
| revert    | 이전 커밋 되돌리기 |

`(ex: feat: 기능 추가)`
